v59 - تحديث داخلي بدون إعادة تنصيب + نسخ احتياطي تلقائي + استعادة عند إعادة التنصيب
=====================================================================================
الملفات: انسخها فوق مجلد البرنامج (app.py, database.py, installer.iss, build.bat, lab_overlay.py, lab_updater.py,
client_builder.py, templates, tools). ملاحظة: tools\seal_client_package.py و make_client_installer.py تغيّرتا (أمان التوكن).

*** تنبيه أمني مهم ***
1) ملف local_config.py في مجلدك فيه توكن GitHub حقيقي، وكان يُنسخ لملف تنصيب العميل، والتوكن نفسه كان محفوظًا
   بإعدادات القاعدة (github_read_token). صلحتُه: الملف والتوكن صارا يُستبعدان من كل ملف عميل جديد.
   ملفات تنصيب سابقة أرسلتها قد تحتوي التوكن -> ألغِ التوكن من GitHub (Settings > Developer settings > Tokens)
   واصنع جديدًا لنفسك فقط. والتوكن الذي رفعته لي بالمحادثة يُعتبر مكشوفًا: ألغِه أيضًا.

الإعداد مرة واحدة (عندك أنت فقط)
1) python -m pip install cryptography
2) python tools\make_update_package.py --init-keys
   - يطلع مفتاح خاص بمجلد المستخدم (%USERPROFILE%\.lab_update_signing_key.pem): خذ نسخة احتياطية، ولا ترسله لأحد.
   - ويطبع سطر PUBLIC_KEY_B64 = "..." ألصقه بأعلى lab_updater.py
3) بنفس الملف اضبط DEFAULT_UPDATE_URL = "https://...." : رابط مجلد عام فيه update.json وملف الزيب
   (مثلاً مستودع GitHub عام: https://raw.githubusercontent.com/<حسابك>/<مستودع>/main/updates ، أو Cloudflare Pages).
   الملفات هناك ما فيها بيانات مرضى ولا أسرار.
4) اعمل Setup جديد للعميل (زر لوحة المصمم أو build) -> هذا الـSetup يحمل المفتاح العام وصار يقبل التحديثات.
   عملاء Setup القديم (قبل v59) يحتاجون Setup واحدًا أخيرًا.

كل تحديث (عندك)
1) عدّل البرنامج، وارفع رقم ملف VERSION (مثلاً 59 -> 60)
2) python tools\make_update_package.py --notes "وصف قصير"
3) ارفع الملفين من مجلد update_packages (update.json + update_60.zip) لنفس عنوان التحديث.
عند العميل: يظهر شريط "يتوفر تحديث [تحديث الآن] [لاحقاً]" (يفحص كل 6 ساعات وعند الفتح، حتى والبرنامج شغّال).
"تحديث الآن" ينزّل ويتحقق من التوقيع ويفحص الكود ثم يعيد التشغيل تلقائيًا؛ "لاحقاً" يؤجّل لحين يريد.

ماذا يضمن
- التحديث يستبدل الكود والقوالب فقط. lis.db والشعار والمرفقات لا تُمس. تُؤخذ نسخة من القاعدة قبل كل تحديث.
- التوقيع: أي ملف تحديث غير موقّع بمفتاحك الخاص يُرفض.
- لو التحديث فيه خطأ ولا يشتغل: يُعزل تلقائيًا ويرجع البرنامج لآخر نسخة سليمة.
- الاستعادة: كل يوم تُنسخ القاعدة إلى C:\ProgramData\LabSystemBackup (آخر 14 يوم). عند تنصيب البرنامج من جديد
  على حاسبة اختفى فيها مجلد البيانات يسأل المنصّب: "هل تريد استعادة النتائج والمعلومات؟". (إن بقي مجلد C:\LabSystem
  بقاعدته فإعادة التنصيب أصلاً لا تمسحها.)
- التحديث لا يضيف مكتبات بايثون جديدة ولا ملفات static (صور/خطوط): هذه تحتاج Setup جديد.
- الأجهزة: iPad/تابلت/موبايل بدون تنصيب: افتح http://<رقم حاسبة المختبر>:9090 من المتصفح (المنفذ مفتوح بالجدار الناري).
