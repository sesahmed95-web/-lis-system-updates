# التحديث التلقائي عبر الإنترنت — دليل الإعداد (للمصمم فقط)

## شنو انضاف؟
- ملف `auto_updater.py`: يتحقق من GitHub عن إصدار أحدث ويحمّله ويثبّته
  تلقائياً فوق نفس مكان التثبيت عند العميل، بدون أي تدخل منه.
- بطاقة جديدة **🌐 التحديث التلقائي عبر الإنترنت** داخل لوحة المصمم
  (`/designer`) — فيها:
  - زر **ربط البرنامج بالإنترنت** / **فصل**: يفعّل أو يوقف الفحص الدوري
    التلقائي (كل 6 ساعات) لهذا الجهاز تحديداً.
  - زر **تحقق من تحديث الآن**: فحص وتحديث فوري يدوي، يشتغل بغض النظر
    عن حالة الربط.
- أيقونة 🛠️ عائمة تظهر بكل صفحات البرنامج فقط لمن سجّل دخوله فعلاً
  كمصمم بنفس المتصفح — تودّيه مباشرة للوحة المصمم.

هذا النظام **منفصل تماماً** عن نظام الترخيص (`license_manager.py`) ولا
علاقة له فيه.

## لماذا GitHub تحديداً؟
لأنه الحل الأرخص (مجاني بالكامل لمستودع خاص واحد وبحجم برنامجك) والأسهل
إعداداً — لا يحتاج منك تشغيل أو صيانة أي سيرفر خاص بك، وGitHub نفسه هو
اللي يستضيف الملفات ويوزّعها بشكل موثوق.

## خطوات الإعداد (تسويها مرة وحدة فقط)

### 1) أنشئ مستودع خاص (Private Repository)
- من حسابك على github.com اضغط **New repository**.
- اختر **Private** (مهم جداً — عشان الكود ما يصير ظاهر للعموم).
- سمّه أي اسم (مثلاً `lis-system-releases`).

### 2) أنشئ Personal Access Token (قراءة فقط، لهذا المستودع فقط)
- من إعدادات حسابك: **Settings → Developer settings → Personal access
  tokens → Fine-grained tokens → Generate new token**.
- **Repository access**: اختر "Only select repositories" وحدد المستودع
  اللي سويته بالخطوة 1 فقط (مو كل مستودعاتك).
- **Permissions → Repository permissions → Contents**: اختر **Read-only**
  فقط (ما تعطيه صلاحية كتابة إطلاقاً).
- انسخ التوكن الناتج فوراً (ما راح يظهر لك مرة ثانية).

### 3) عبّي الإعدادات داخل `auto_updater.py`
افتح `lis_system/auto_updater.py` وعبّي أول 3 قيم:
```python
GITHUB_OWNER = "اسم-حسابك-بـGitHub"
GITHUB_REPO = "lis-system-releases"
GITHUB_TOKEN = "التوكن-اللي-نسخته-بالخطوة-2"
```

### 4) عند كل تحديث جديد تريد توزيعه — 3 خطوات بس
1. عدّل رقم الإصدار بملف `lis_system/VERSION` (رقم أكبر من السابق،
   مثلاً من `15` إلى `16`).
2. اضغط مجلد `lis_system` كامل بصيغة **zip** (نفس المجلد اللي فيه
   `app.py`, `templates/`, `static/`... إلخ).
3. من صفحة المستودع على GitHub: **Releases → Draft a new release**،
   اختر **Tag** بنفس رقم الإصدار (مثلاً `16` أو `v16` — المهم يحتوي
   نفس الرقم)، وارفع ملف الـ zip كـ **Asset**، ثم **Publish release**.

هذا كل شي. أي جهاز عميل "مربوط بالإنترنت" (فعّل الزر من لوحة المصمم
عنده) راح يتحقق تلقائياً خلال أقصى 6 ساعات، يلقى الإصدار الجديد، ينزّله،
ويعيد تشغيل البرنامج بآخر نسخة تلقائياً — بدون أي تدخل من العميل.

## ملاحظات مهمة
- التحديث التلقائي **لا يمسح قاعدة بيانات العميل** (`lis.db`) ولا أي
  صور شعار مرفوعة — نفس استثناءات `update.ps1` اليدوي القديم تنطبق هنا
  بالضبط (يستخدم نفس السكربت بالضبط، فقط بمصدر مختلف).
- إذا جهاز العميل ما عنده إنترنت وقت الفحص، يفشل الفحص بصمت ويعيد
  المحاولة بعد 6 ساعات — ما يوقف أو يعطّل البرنامج أبداً.
- التوكن اللي تحطه بـ`auto_updater.py` ينتشر داخل نسخة كل عميل (لأنه
  لازم يقدر يقرأ الـ Releases من مستودعك الخاص). لهذا السبب حصرناه
  بصلاحية **قراءة فقط على هذا المستودع تحديداً** — حتى لو استخرجه أحد
  من ملفات البرنامج، أقصى ما يقدر يسويه هو تنزيل نفس ملفات التحديث
  العامة، وما يقدر يكتب أو يوصل لأي مستودع أو حساب آخر عندك.
- الميزة تعمل على Windows فقط حالياً (لأنها تعتمد على `update.ps1`
  الموجود أصلاً، وهو مبني لـ Windows تحديداً مثل باقي سكربتات التشغيل).
